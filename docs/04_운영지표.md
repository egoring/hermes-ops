# 운영 지표

> 규칙을 바꿨을 때 효과가 있었는지 숫자로 본다.
> 도구: `python3 ~/hermes-ops/scripts/kanban_metrics.py [보드] [--days N] [--weekly]` (DB 읽기 전용)

## 1. 지표 정의

| 지표 | 정의 (kanban.db) | 목표/해석 |
|---|---|---|
| 반려율 | `review_requested`가 있던 태스크 중 `changes_requested` ≥1 인 비율 | 낮을수록 좋지만 0이 목표는 아니다. 반려 대부분이 실질 결함이면 리뷰가 일하는 것 |
| 3회 상한 도달 | `changes_requested` ≥3 태스크 수 | 늘면 스펙 품질 문제 → 재설계 |
| 크래시 | `crashed` 이벤트 (worker 프로세스 소멸) | 0에 가깝게 |
| 잠금 만료 회수 | `reclaimed` 중 payload에 `stale_lock` | 작업 유실. 0이 목표 |
| 규칙 위반 종료 | `protocol_violation` (complete/block 없이 종료) | 0 |
| 승인-block | `blocked`/`block_loop_detected` 사유에 "승인" | 0 (결정 권한 규칙) |
| 태스크별 모델 지정 | 기간 내 생성 태스크 중 `model_override` 있음 | 모델 배정 규칙(§5.6) 적용 확인 |
| 중앙 run 시간 | 프로필별 `task_runs.ended_at - started_at` 중앙값 | 급변하면 원인 확인 |
