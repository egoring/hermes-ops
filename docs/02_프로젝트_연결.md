# 프로젝트 연결

> 봇은 그대로 두고 **폴더 + AGENTS.md + 보드** 로 프로젝트를 붙인다.
> 아래 이름·경로는 모두 예시다. 실제 연결 정보는 `../projects/<이름>.md`에 두고 **git에 올리지 않는다** (`.gitignore`, 양식은 `projects/example.md`).

## 1. 연결 예시

| 프로젝트 | 폴더 | 보드 | 문서 | 상태 |
|---|---|---|---|---|
| 상위 폴더 (공통 규칙) | `~/work` (git 루트) | — | `projects/work.md` | 활성, `terminal.cwd` |
| └ 웹 서비스 | `~/work/webapp` | `webapp` | `projects/webapp.md` | 활성 |
| └ 데이터 분석 | `~/work/analysis` | `analysis` | `projects/analysis.md` | 대기 |

상위 폴더에는 하위 프로젝트가 함께 쓰는 규칙(작업 위치, 보고 형식, 리뷰 기준)만 두고, 프로젝트별 규칙은 각 폴더의 `AGENTS.md`에 둔다.

## 2. 새 프로젝트 붙이기

| 순서 | 할 일 | 비고 |
|---|---|---|
| 1 | 프로젝트 폴더 준비. 여러 하위 프로젝트가 규칙을 공유하면 상위 폴더 + git 루트로 만든다 | git 루트여야 상위 AGENTS.md가 연쇄 로드된다 |
| 2 | `AGENTS.md` 작성 (아래 §4 템플릿) | 초안은 reviewer-bot에게 "기존 프로젝트 AGENTS.md 구조대로" 요청. **완료 기준 수치는 사용자가 정한다** |
| 3 | 보드 생성: `hermes kanban boards create <slug> --default-workdir <폴더>` | `--default-workdir` 옵션 존재 확인(v0.21.4 도움말). 기존 보드 변경은 `boards set-default-workdir`. 새 보드 생성은 아직 실제로 해보지 않았다 |
| 4 | Discord 대화도 이 프로젝트 기준으로 할지 결정 → §3 | kanban만 쓰면 생략 가능 |
| 5 | 행동 테스트 T3·T6 (`01_운영구조.md` §7.2) | T3에 새 프로젝트 검증 기준이 나와야 한다 |
| 6 | `projects/<이름>.md` 작성, §1 표·`변경이력.md` 갱신, 커밋 | |

SOUL, 봇 설정, 게이트웨이는 건드리지 않는다(§3의 `terminal.cwd` 제외).

## 3. Discord 대화의 기준 폴더 (`terminal.cwd`)

kanban worker는 보드 `default_workdir` 덕에 항상 맞는 AGENTS.md를 받는다. **Discord 스레드만** `terminal.cwd`를 따른다.

| 방식 | 방법 | 장점 | 단점 | 언제 |
|---|---|---|---|---|
| A. 활성 프로젝트로 전환 | 프로젝트를 바꿀 때 봇 3개 `terminal.cwd` 변경 + 게이트웨이 재시작 | 대화가 곧바로 그 프로젝트 규칙 | 전환마다 재시작(승인), 동시 진행 불가 | 한 번에 하나만 할 때 (현재) |
| B. 공통 상위 폴더 | 모든 프로젝트를 `~/work/` 같은 상위 폴더 아래에 두고 cwd를 거기로. 상위 AGENTS.md는 "첫 메시지의 프로젝트 이름으로 폴더를 고르고 그 AGENTS.md를 읽어라"만 둔다 | 재시작 없음, 동시 진행 가능 | 첫 메시지에 프로젝트를 안 밝히면 규칙 없이 시작. 프로젝트 폴더 이동 필요 | 프로젝트가 2개 이상 동시에 돌 때 |
| C. 채널 분리 | 프로젝트마다 Discord 채널 + `platforms.discord.channel_overrides[<채널>]` | 채널마다 모델·`system_prompt`를 다르게 줄 수 있다 | **cwd는 채널별로 못 바꾼다** (`gateway/config.py` ChannelOverride = model/provider/system_prompt, 2026-09-29 확인). system_prompt에 "이 채널은 <폴더> 프로젝트, 그 AGENTS.md부터 읽어라"를 넣는 우회만 가능 | B와 함께 쓸 때 |

권장: 프로젝트가 하나면 A로 시작하고, 두 번째 프로젝트가 동시에 필요해지면 B로 옮긴다. 옮길 땐 기존 폴더를 새 상위 폴더로 옮기고 옛 경로에 심볼릭 링크를 남긴다(예: `ln -s ~/work/webapp ~/webapp`). 그러면 옛 절대경로를 참조하는 스크립트·문서가 그대로 동작한다.

## 4. 프로젝트 AGENTS.md 템플릿

```markdown
# AGENTS.md — <프로젝트> 규칙
> 보드 `<slug>` · 작업 기록 `docs/<작업기록>.md` · 실행 환경 `<venv 등>`

## 0. 목표와 평가 기준     # 무엇이 "좋아졌다"인가
## 1. 검증 세트            # 완료 기준을 재는 명령·데이터·기준선·통과선 (수치)
## 2. 도메인 규칙          # 데이터·API·환경 제약
## 3. 코드·도구 규칙       # 반드시 쓸 헬퍼, 금지 패턴
## 4. 구조                 # 주요 파일, 현행 기준선
## 5. 실패한 아이디어      # 다시 하지 않을 것과 이유
## 6. 보고 보충            # 보고서에 반드시 들어갈 측정 조건
## 7. 리뷰 보충            # 이 프로젝트의 🔴 예시, 재발 함정 체크리스트
## 8. override 기록        # 사용자 결정으로 기준 미달 진행한 사례
```

역할 정의·리뷰 절차·결정 권한은 SOUL에 있으므로 다시 쓰지 않는다.
