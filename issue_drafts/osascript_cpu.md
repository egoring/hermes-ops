# [macOS] launchd gateway: `/usr/bin/osascript` wrapper burns ~5% CPU while idle

## Environment
- Hermes Agent v0.21.4 (2026.9.21), upstream `d2ef7db7`
- macOS 26.6.2, Apple Silicon
- Gateway installed as LaunchAgent `ai.hermes.gateway` (multiplex, 4 profiles, Discord only — no LAN endpoints)
- plist generated by `hermes_cli/gateway_launchd.py::launchd_program_arguments` (#71206 Local Network identity wrapper)

## Symptom
The `osascript -e 'do shell script "exec … gateway run --external-supervisor …"'` wrapper process uses ~5% CPU continuously, while the actual gateway process it launched idles at ~0.3%.

| Measurement | osascript wrapper | gateway (python) |
|---|---|---|
| `top`, 6 samples at 10 s intervals | 4.8–5.1 % | 0.2–0.3 % |
| CPU-time delta over 60 s | 3.14 s (≈5.2 %) | 0.20 s (≈0.3 %) |
| CPU-time delta over 10.5 h awake | 28 m 39 s (≈4.6 %) | 1 m 42 s (≈0.3 %) |
| Cumulative after ~29 h uptime | 43 m 26 s | 3 m 02 s |

After removing the wrapper from `ProgramArguments` (running the `stderr_timestamp` → gateway command directly), the wrapper cost disappears. The `stderr_timestamp` process uses 0.0 %, and the gateway uses 0.5–1.0 % right after start. `hermes gateway restart` keeps the hand-edited plist (verified twice); `update` / `gateway start` / `gateway install` regenerate it.

## Expected
The wrapper should not cost more CPU than the gateway it supervises. A likely cause is `do shell script` polling or buffering the child's output. The docstring notes that it buffers stdout/stderr until exit, but in this setup both streams are already redirected to files.

## Workaround
Edit the plist by hand to drop the wrapper. The trade-offs are that LAN connections from the gateway fail again (EHOSTUNREACH, which is the original #71206 problem), `hermes gateway status` reports the service definition as stale, and the next `hermes update`, `gateway start` or `gateway install` restores the wrapper.

## Suggestion
- Make the wrapper opt-in or opt-out (for example, `gateway.launchd.local_network_wrapper: auto|on|off`). It could be enabled only when a profile has a LAN `base_url` or LAN platform endpoints.
- Alternatively, use a wrapper that does not busy-wait.

## Related

- #123118 — the same wrapper shows as an opaque `osascript` entry in Privacy & Security
